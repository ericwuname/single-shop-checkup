### 4.2 M6-2 数据安全

| 权 | 实现 |
|---|---|
| **一键导出** | `GET /api/shops/{id}/export` → 一个 xlsx，9 个 sheet（录入/排班/商品/采购/入库/盘点/报废/供应商/应付）。设计成"一个文件全拿走"：老板要的是"我的数据"，不是"你的七个表" |
| **删除权** | `DELETE /api/shops/{id}/data` → **真的删行**，不是软删标志位。必须带 `X-Admin-Token`；**服务端没配口令就整体禁用**（宁可持续不可用，不默认放行） |

### 4.4 M6-4 稳定性

| 项 | 实现 |
|---|---|
| **SQLite 并发** | WAL + `busy_timeout=5000` + `synchronous=NORMAL`。WAL 让读写不互斥；busy_timeout 让拿不到写锁时等 5 秒而不是立刻抛 "database is locked"（老板看到的就是"保存失败"） |
| **请求日志** | `ErrorLogMiddleware` 记录 4xx/5xx。**绝不记请求体** —— 营业额是老板的商业秘密，日志里出现这些数字等于把账本摊在日志文件里。只记方法/路径/状态码/店 id/耗时 |
| **健康检查** | `/api/health` 现在报 `db_writable`。用 `BEGIN IMMEDIATE` 抢一次写锁再回滚来验证——**不写数据、不建表**，但能证明磁盘没满、文件没被挂成只读。"能读不能写"时原来照样返回 ok，监控一片绿而老板的录入全在失败 |
| **优雅降级** | `web/src/offline_queue.js`：保存遇到**网络层失败** → 写 localStorage，明确提示"已存到手机里，连上网自动补传"；启动时和每次保存成功后都尝试补传。**只对 PUT /api/daily 暂存**（幂等覆盖写，补传不重复）；POST 类不暂存（会重复） |
| **限流** | `RateLimitMiddleware`：单店每分钟写请求上限（默认 120）。**按店不按 IP**（M0 阶段大家基本在同一个 NAT 后面，按 IP 会误伤）；**只限写不限读**（读打不坏数据库，限它只会让老板打不开页面）；`/api/health` 豁免（监控每秒打一次） |

## 6. 我改掉的 / 踩到的坑（诚实清单）

| # | 性质 | 内容 |
|---|---|---|
| 1 | 🔴 **测试数据连带失效（3 处）** | 改「且"后，M5 写的三条测试数据不够比例了：600 元报废没采购数据当分母（比例算不出来）；盘亏 5 瓶/100 瓶 = 5% 刚好卡在阈值上（不 > 5%）。**已调数据并在注释里写明为什么调** —— 不是悄悄改数字 |
| 2 | 🔴 **语义翻转（1 处）** | `test_scrap_small_amount_but_huge_ratio_needs_approval` 从"必须拒"翻转成"金额没过线就不拒"。**显式留痕**：docstring 写清 M5 时它测的是什么、M6 为什么反了 |
| 3 | 🟠 **「通过审核」一度是死条件** | `explained_loss_amount` 初版给 `needs_approval` 传了 `base=None` → 比例永远算不出来 → "且"语义下 need 永远 False → 第二个条件永不触发。自查抓到，改成与审批路由同口径（**当月该货采购额**） |
| 4 | 🟠 **顺带发现一个产品事实** | "且"阈值下，无审批人的大额报废**根本录不进来**（400 拒）。所以"有原因但没签字"这条只在老数据/直接写库里存在。测试改为 ORM 造一条来验口径，并在注释里说明为什么走不通 HTTP —— **不假装 HTTP 能过** |
| 5 | 🟡 导出中文文件名炸了 | `Content-Disposition` 直接塞中文 → `UnicodeEncodeError: 'latin-1' codec`。改 RFC 5987（`filename*=UTF-8''...`）+ ASCII fallback |
| 6 | 🟡 备份同秒连备两次撞名 | `VACUUM INTO` 不允许覆盖已存在文件 → `output file already exists`。加序号，**备份任务不该因为"备得太快"而失败** |
| 7 | 🟡 中间件不能启动后加 | 测试里 `app.add_middleware` 抛 `RuntimeError: Cannot add middleware after an application has started`。改成造一个只挂该中间件的小 app 来测 —— 顺带证明中间件是自包含的 |
| 8 | ⚪ **C 盘爆满（99%，剩 3.1G）** | pytest 临时目录累积了 1.7G（每次跑测试建一套临时 SQLite）。已清。**这个项目跑测试很吃 C 盘空间**，建议定期清 `%TEMP%\pytest-of-87465` |
