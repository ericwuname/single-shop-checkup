## 1. 环境分离（先做这个，再谈上线）

```bash
# dev：本机开发库（合成数据在这里）
CHECKUP_DB=data/checkup.db
# prod：真店数据库。**合成数据绝不进 prod**（docs/06 §2.4）
CHECKUP_DB=data/prod.db
ADMIN_TOKEN=<自己生成的一串随机字符>
RATE_LIMIT_PER_MINUTE=120
```

用两个 `.env` 文件管（`.env.dev` / `.env.prod`），`python-dotenv` 已装。
**prod 库要单独建**，不要从 dev 拷 —— 拷过去就把合成数据带进去了。

```bash
# 建一个干净的 prod 库（不带任何合成数据）
CHECKUP_DB=data/prod.db python -c "from server.db import init_db; init_db()"
CHECKUP_DB=data/prod.db python -c "
from server.seed_metrics import seed_all
from server.db import session_scope
with session_scope() as s: seed_all(s)
"
```

## 2. 把服务做成"开机自启 + 崩溃自动重启"

### Windows（你的本机，零成本档）

用 **NSSM**（Non-Sucking Service Manager）把 uvicorn 包成服务：

```powershell
# 1) 装 NSSM（choco 或去 nssm.cc 下载）
choco install nssm -y

# 2) 注册服务
nssm install CheckupAPI "C:\Users\87465\.workbuddy\binaries\python\envs\single-shop\Scripts\python.exe"
nssm set CheckupAPI Arguments "-m uvicorn server.main:app --host 127.0.0.1 --port 8000"
nssm set CheckupAPI AppDirectory "D:\0.个人文档\个人文档\单店模型项目\single-shop-checkup"
nssm set CheckupAPI AppEnvironmentExtra CHECKUP_DB=data/prod.db ADMIN_TOKEN=<你的口令>
nssm set CheckupAPI AppStdout "D:\0.个人文档\个人文档\单店模型项目\single-shop-checkup\data\logs\api.log"
nssm set CheckupAPI AppStderr "D:\0.个人文档\个人文档\单店模型项目\single-shop-checkup\data\logs\api.err"
nssm set CheckupAPI Start SERVICE_AUTO_START
nssm set CheckupAPI AppExit Default Restart        # 崩溃自动重启
nssm set CheckupAPI AppRestartDelay 5000

# 3) 起服务
nssm start CheckupAPI
nssm status CheckupAPI
```

### Linux（正式档，腾讯云轻量）

```ini
# /etc/systemd/system/checkup.service
[Unit]
Description=Single Shop Checkup API
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/checkup
Environment=CHECKUP_DB=/opt/checkup/data/prod.db
Environment=ADMIN_TOKEN=<你的口令>
ExecStart=/opt/checkup/venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now checkup
sudo systemctl status checkup
```

## 3. HTTPS + 公网地址

### 零成本档：Cloudflare Tunnel

```bash
# 1) 装 cloudflared（winget install Cloudflare.cloudflared）
# 2) 登录并建隧道
cloudflared tunnel login
cloudflared tunnel create checkup
cloudflared tunnel route dns checkup 你的域名.top

# 3) 配置文件 %USERPROFILE%\.cloudflared\config.yml
# tunnel: <TUNNEL-ID>
# credentials-file: C:\Users\87465\.cloudflared\<TUNNEL-ID>.json
# ingress:
#   - hostname: checkup.你的域名.top
#     service: http://127.0.0.1:8000
#   - service: http_status:404

# 4) 起隧道（同样建议包成服务）
cloudflared tunnel run checkup
```

Cloudflare 自动签证书、自动续、**禁明文 HTTP**（docs/06 §2.2）。

### 正式档：Caddy（自动 HTTPS）

```bash
# /etc/caddy/Caddyfile
checkup.你的域名.top {
    reverse_proxy 127.0.0.1:8000
}
```

Caddy 自动申请并续期 Let's Encrypt 证书，配置文件就这两行。

## 5. 迁移验证（上线前必跑）

```bash
# 1) 备份 dev 库（万一搞错还能回退）
python scripts/backup.py --db data/checkup.db --dir data/backups --keep 30

# 2) 在 prod 库上重建结构 + 指标种子（不带合成数据）
CHECKUP_DB=data/prod.db python -c "from server.db import init_db; init_db()"
CHECKUP_DB=data/prod.db python -c "
from server.seed_metrics import seed_all
from server.db import session_scope
with session_scope() as s: seed_all(s)
"

# 3) 起服务，跑 verify_m2（45 项判据）
CHECKUP_DB=data/prod.db python -m uvicorn server.main:app --host 127.0.0.1 --port 8000 &
python scripts/verify_m2.py
```

> ⚠️ `verify_m2.py` 对的是**合成三年数据**的基线。prod 库里没有那批数据，
> 所以这一步在 prod 上不会全绿 —— 它的作用是证明"结构 + 指标注册表迁过去没坏"。
> **真库的判据是 M0 期间的 daily 对账**（老板口述的数 vs 系统算的数）。

## 6. 每日备份（开机计划任务）

```powershell
# Windows 任务计划程序，每天 23:50 跑一次：
schtasks /Create /TN "CheckupDailyBackup" /SC DAILY /ST 23:50 /TR "python D:\...\single-shop-checkup\scripts\backup.py --db data\prod.db --dir data\backups --keep 30"
```

**异机存放**（docs/06 §3.1 要求）：备份不能只在本机。

```powershell
# 手动/计划任务同步到 U 盘或另一台机器
robocopy "D:\...\single-shop-checkup\data\backups" "E:\checkup-backups" /MIR
```

对象存储（COS/OSS）自动上传**未实现** —— 要花钱，等你确认预算。
在那之前，U 盘/另一台电脑/网盘客户端都满足"异机"。

## 7. 监控

| 项 | 做法 |
|---|---|
| 健康检查 | `GET /api/health` —— 现在会报 `db_writable`（M6-4） |
| 外拨监控 | UptimeRobot（免费档）加一个 HTTP 监控，指到 `https://checkup.你的域名.top/api/health` |
| 宕机通知 | UptimeRobot 免费档支持邮件通知 |

`/api/health` 返回 `status: "degraded"` 时，UptimeRobot 会标红 —— 这就是 M6-4 加可写检查的目的：
**能读不能写**（磁盘满、只读挂载）时不再假报正常。
