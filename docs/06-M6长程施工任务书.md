## 2. M6-1 · 部署上云（P1 重头）

**为什么现在做**：M0 通过后，店要每天用，服务必须 7×24 可访问——本机 localhost 做不到。
而且你自己在外面用手机录数，也需要一个公网地址。

### 两档方案（预算优先）

| 档 | 方案 | 成本 | 适用 |
|---|---|---|---|
| **零成本档** | 本机 + **Cloudflare Tunnel**（内网穿透） | 0 元（需一个域名，`.top/.xyz` 首年几块钱） | M0 期间先用：你在家电脑开机时老板才能用 |
| **正式档** | 腾讯云轻量 2C2G + 域名 + HTTPS | ≈ **112 元/年**（新用户） | M0 通过后立刻切 |

**执行内容（两档通用）**：

| # | 项 | 要求 |
|---|---|---|
| 1 | 打包 | `uvicorn` 用 systemd / NSSM 做成服务，**开机自启、崩溃自动重启** |
| 2 | HTTPS | Cloudflare 或 Caddy 自动证书，**禁明文 HTTP** |
| 3 | 访问控制 | 门店码（现有 shop 机制）+ 一个简单的管理口令。**不做完整用户体系**（M0 不需要） |
| 4 | 环境分离 | `prod` 与 `dev` 两套库；**合成数据（测试店A）绝不进 prod** |
| 5 | 迁移验证 | 把 `data/checkup.db` 的真实结构库完整迁到云端跑一遍 `verify_m2.py`，45 项必须过 |

**验收**：手机 4G（不连 WiFi）打开 H5，能完成一次完整录入并出报告；服务重启后数据无损。

## 3. M6-2 · 数据安全（真实老板数据进来之前必须有）

| # | 项 | 要求 |
|---|---|---|
| 1 | **每日自动备份** | SQLite `VACUUM INTO` 每日一次，保留最近 30 份；备份文件**异机存放**（云对象存储，几块钱/月） |
| 2 | **一键导出** | 老板随时能把自己的数据导成 Excel 拿走——**数据是他的，不是我们的** |
| 3 | **删除权** | 老板要求删除时，能完整删掉该店全部数据（含备份中的处理说明） |
| 4 | 声明 | 页面上明示：「数据只存在你的店的空间里，不用于任何其他用途」 |
| 5 | 恢复演练 | **真删一次、真恢复一次**，把过程写进交付报告。没演练过的备份等于没有备份 |

| # | 项 | 要求 |
|---|---|---|

| 5 | 限流 | 单店每分钟请求数上限，防误操作打爆 |
