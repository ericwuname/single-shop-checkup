## 1. 三条试用路径对比

| | A 同一个 Wi-Fi | B Cloudflare Tunnel | C Tailscale |
|---|---|---|---|
| **前提** | 手机和电脑连同一个路由器 | 一个域名（几块钱/首年）+ 免费注册 | 免费 Tailscale 账号（手机+电脑各装一个） |
| **电脑关机后** | ❌ 手机打不开 | ❌ 打不开（隧道跑在电脑上） | ❌ 打不开（同左） |
| **手机在 outside** | ❌ 不行 | ✅ 4G 也行 | ✅ 4G 也行（仅你自己的设备） |
| **暴露公网** | 否（仅局域网） | 是（有访问码挡着，WP-1） | 否（私有网络） |
| **适合** | 头三天在家先试 | M0 期间长期用 | 不想买域名时的长期方案 |

**共同点：电脑关机 = 服务停**。因为服务跑在你电脑上（M6 部署手册 §2 的方式）。
要 7×24，得上云服务器（≈112 元/年，docs/09 §2 决策树）——**等你决定，我不擅自买**。

## 2. 怎么选（抄自 docs/09 §2 决策树）

1. 只想这三天先试起来 → **路径 A**（零配置，5 分钟）
2. 要在外面（店里/路上）录数，且有域名 → **路径 B**（配 Cloudflare Tunnel，M6 部署手册 §3）
3. 要在外面录数，不想买域名 → **路径 C**（Tailscale 免费档）

## 3. 访问码：生成、放置、使用

```powershell
# 生成一个（复制输出）
python -c "import secrets; print(secrets.token_urlsafe(24))"
```

* 放在项目根目录的 **`.env`** 文件里（`.env.example` 抄一份改名），两行：
  `PUBLIC_MODE=1` 和 `APP_ACCESS_KEY=<刚生成的码>`
* **绝不提交进仓库**（`.gitignore` 已挡），**绝不发给微信**——要发就用别的方式口头给
* 只有路径 B（公网）需要它；路径 A/C（局域网/私有网）`PUBLIC_MODE` 留空，手机不需要输码
* 手机第一次打开：出现"访问码"输入框 → 粘贴 → 进入。浏览器会记住，下次不用再输
* 丢了：改 `.env` 里的码重启服务，旧码立即失效；手机上退出重进输新码

## 4. 安卓安装到主屏幕

* Chrome 打开网站 → 菜单（右上角 ⋮）→「**添加到主屏幕 / 安装应用**」
  —— **未核实：以官方文档为准**（https://support.google.com/chrome/answer/9658369）
* ⚠️ **纯 `http://局域网IP` 下通常只能添加为快捷方式，装不成完整应用**——
  完整 PWA（自己的图标、全屏运行）需要 HTTPS（路径 B/C）。

## 5. Windows 常驻

* **开机自启**：NSSM 注册服务（M6 部署手册 §2.1 有完整命令），或任务计划程序
  触发器设"登录时"，操作填 `scripts\start_server.bat`
* **关闭睡眠**：设置 → 系统 → 电源 → 屏幕和睡眠 → "睡眠"改为**从不**（接通电源时）。
  —— **未核实：Windows 设置项名称随版本有差异，以系统实际显示为准**
* **断电/重启后确认活着**：本机浏览器打开 `http://127.0.0.1:8000/api/health`，
  看到 `"status": "ok"`（以及 `"db_writable": true`）就是活的

## 6. 备份

```powershell
# 手动备一次（也可以挂任务计划每天自动跑，见 M6 部署手册 §6）
python scripts/backup.py
```

## 7. 七天自证表（M0 开始前，你本人先跑一遍）

| 天 | 做什么 | 检查什么 |
|---|---|---|
| 第 1 天 | 建店、填房租/水电/工钱、录当天的数 | 报告三行出得来；数字与手算一致 |
| 第 2 天 | 正常录 | 昨天的数还在；"本周"柱子出现 2 根 |
| 第 3 天 | 开飞行模式录一条 → 关飞行模式 | "已存到手机里"提示；联网后自动补传 |
| 第 4 天 | 故意输一个错码（公网模式） | 提示"需要访问码"；连错 10 次会被锁 10 分钟 |
| 第 5 天 | 加到主屏幕；重启电脑 | 图标是自己开的；重启后服务自动活了（NSSM） |
| 第 6 天 | 手工备份一次；用导出按钮 | 拿到 xlsx；Excel 打开数字对得上 |
| 第 7 天 | 回看"本周" | 平均 = 合计 ÷ 有数天数（不是 ÷7）；保本卡数字合理 |

七天全过 → M6 门禁 2 的自证项完成，可以拿着手册去教老板了。

## 8. 故障排查

| 症状 | 检查 |
|---|---|
| 手机打不开 | ① 电脑上 `curl http://127.0.0.1:8000/api/health` 活着吗；② 路径 A 时两台设备在同一 Wi-Fi？；③ 电脑防火墙放行 8000 端口了吗 |
| 提示"需要访问码" | 码输对了吗；`.env` 里 `PUBLIC_MODE=1` 了吗（局域网试用不需要它，关掉就不问码了） |
| 提示"尝试太多次" | 连续错码触发了暴力防护。等 10 分钟，或重启服务（内存计数会清零） |
| 保存失败 | 看手机是不是飞行模式；"已存到手机里"的数联网后自动补传，不用重录 |
| 数据没补传 | 手机连上网后**打开页面**（补传发生在打开时），别杀后台 |
| 重启后连不上 | NSSM 服务在吗（`nssm status CheckupAPI`）；`/api/health` 的 `db_writable` 是 false = 磁盘满了 |

## 9. 每次发版（改了代码之后）

1. `cd web && npm run build`（构建新前端）
2. 重启服务（NSSM 会自动拉起；手动跑的 Ctrl+C 再启）
3. **把 `web/public/sw.js` 第 9 行的 `checkup-v1` 加一**（`v2`、`v3`…）——不改这个，
   手机上的旧 Service Worker 会继续用缓存的旧资源
4. 手机上：关掉旧页签，重新打开网站；如果界面没变，下拉刷新一次
   （新 SW 接管时会自动刷新一次，这是 `main.js` 里写好的行为）
