# M0 操作手册（一页纸）

> 给**你本人**用的：怎么收数、怎么录、怎么回三行。
> 打印出来或存手机备忘录。**不用装任何 App**，一个浏览器就够。

---

## 1. 每天只要三个数

见到老板，就问这三句（**别提"系统/软件/数字化"**）：

> 1. 今天卖了多少钱？
> 2. 今天买菜花了多少？
> 3. 小李和老张今天各上几点到几点？

**不要钱，先说清楚。** 也先说清"先试两周，没用就停"。

---

## 2. 怎么录

1. 手机浏览器打开 `https://<你的域名>/`（部署好后填真地址）
2. 选门店 → 填今天的三个数 → 有排班就加一行
3. 点保存，**等它出结论再走**（大概 1–2 秒）

**关掉 WiFi 用 4G 也能录** —— 信号差的时候页面会先存本地，连上了自动补传（M6-4 已做）。
如果看到"保存中"转很久，**刷新页面比反复点保存管用**（连点会触发限流，那是为了保护数据）。

---

## 3. 怎么回三行

收到数之后，按这个格式回（**禁财务术语**）：

```
第 1 行：数字      今天营业额 4200，人工 100（占 2.4%），食材 1100（占 26.2%）。
第 2 行：判断      食材占比偏低，可能是采购漏记了，也可能在消化存货。
第 3 行：一个动作  明天把采购的票据留着，晚上对一遍是不是有漏记的。
```

话术照着 `docs/回话速查卡.md` 念就行 —— 数字落在哪一档，念对应那句。

---

## 4. 老板问"为啥"的时候怎么答

| 他问 | 你答 |
|---|---|
| "这玩意儿要钱吗？" | "不要钱。就是帮你把每天的数记下来，看看钱花在哪。" |
| "你要我这些数干啥？" | "帮你看出哪个环节在漏。比如这个月食材占比比上月高了 5 个点。" |
| "我的数据安全吗？" | "只存在你的店的空间里，不用于任何其他用途。你随时能导成 Excel 拿走，也可以让我全删掉。" |
| "是不是要装软件？" | "不用，手机浏览器打开就能用。" |
| "我没空每天记" | "就三个数，三十秒。你先试两周，没用就停。" |

**他要是说"看不懂/不想填/填错了"，当场原话记进 `docs/M0-老板反馈记录.md`，不要自己改设计。**

---

## 5. 出问题时怎么办

| 情况 | 处理 |
|---|---|
| 页面打不开 | 先看 `https://<域名>/api/health` 是不是 `status: ok`。不是 → 服务挂了，重启 |
| 录进去但数字不对 | 当天改掉重存（同一张单重复保存是**覆盖**，不会重复） |
| 报"这一分钟提交太多次" | 等 60 秒，或刷新页面 |
| 数据库满了/只读 | `/api/health` 会显示 `db_writable: false` —— 这就是加这个检查的原因 |
| 数据丢了 | `python scripts/backup.py --restore <备份文件>`（见 `docs/M6-部署手册.md` §8） |

## 6. 七天自证演练（门禁 2 要求）

**M0 开始前，你本人先用手机连续录 7 天自己的数。**
这不是形式 —— 是为了让你在教老板之前，先把"信号差时怎么存"、
"录错了怎么改"这些坑自己踩一遍。

演练完在 `docs/M0-老板反馈记录.md` 记一行：第几天卡的、卡在哪。
