# M0 · 老板反馈记录（B 线专用）

> 任务书 §2 原话：**"老板反馈的任何『看不懂 / 不想填 / 填错了』，当天记录，不要自行改设计，等 M0 结束统一评估。"**
>
> 这份文件就是"记录"的落点。**执行窗口在 M0 期间只往这里写，不改代码。**
> 原因：单个老板的一句话 ≠ 需求。三家店都说同一句，才是需求。

---

## 用法

1. 每天跟老板对完话，**当天**在下面"逐日记录"里追加一段
2. 只记**他的原话** + 当时的场景，**不要翻译成需求**（"他嫌麻烦" vs "他说第三个数总要翻本子"——后者才能改）
3. 不要因为某条反馈去改代码 / 改设计。改之前等 M0 结束统一评估

---

## 硬指标（门禁）

| 项 | 要求 |
|---|---|
| 店数 | 3 家（喜洋洋优先 + 家附近的快餐/面馆） |
| 时长 | **连续 14 天** |
| 主动性 | **老板主动发**（不是催出来的）。催出来的数据，上线后一样要催 —— 那不是产品，是外包 |
| 付费意愿 | **≥1 家明确愿付费** |

---

## 每天要他发的三个数

```
营业额 4200，买菜 1100，小李 18-22，老张 18-22
```

## 开场话术（照抄，不提"系统/软件/数字化"）

- 明确**不要钱**
- 明确**先试两周，没用就停**
- 说清**只要三个数**

---

## 逐日记录

> 模板：日期 / 哪家店 / 他的原话 / 我的回复 / 归类（看不懂 / 不想填 / 填错了 / 主动加东西）

| 日期 | 店 | 他的原话（照抄） | 我的回复 | 归类 |
|---|---|---|---|---|
| （例）2026-10-18 | 喜洋洋 | "买菜这个数是当天买的还是当天用的？" | 告诉他按**当天买**记 | 看不懂 |

---

## M0 结束时要回答的四个问题

1. **有几家店撑过了 14 天？** 没撑过的是在第几天断的、为什么？
2. **有没有一天是他主动发的？** 第一次主动发是在第几天？
3. **"三个数"有没有少过一个？** 少的是哪个 —— 那个数就是录入成本最高的地方
4. **有没有人问过"能不能付钱"或"这个对我有啥用"？** 原话是什么？

> 这四个问题的答案决定 M5-3（拍照识别）要不要开工，也决定 M5-4（商业化）能不能开。
> **代码回答不了这四个问题。**

## 与 A 线的关系

| 线 | 内容 | 状态 |
|---|---|---|
| **B 线** | M0：找 3 家店跑 14 天 | 🔴 **最高优先级，用户本人做** |
| A 线 | M5-0 / M5-1 / M5-2 | ✅ 已完成（见 M5 交付报告） |
| A 线 | M5-3 拍照识别 | ⏸ **暂缓** —— M0 反馈"老板嫌录入麻烦"才开工 |
| A 线 | M5-4 商业化 | ⏸ **不做** —— M0 出现付费意愿之前不动 |

**A 线抢在 B 线前面是有害的**：M0 反馈回来若推翻某个设计，A 线做的功能可能白做。
