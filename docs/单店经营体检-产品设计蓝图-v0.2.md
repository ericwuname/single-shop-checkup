## 1. 对本次补充需求的三条评估

### 1.1 ✅ 判断正确、且是全场唯一差异化的两条

| 你的原话                       | 专业术语                      | 为什么这是差异化                                                                          |
| -------------------------- | ------------------------- | --------------------------------------------------------------------------------- |
| **「销售出库的数据能否与库存数据对得上」**    | **账实相符 / 三单匹配（订单–到货–发票）** | 这是**内控审计的核心命题**，不是 ERP 功能。市面所有进销存都能记数，但**没有一个小微产品把"账实差异"当成第一等公民**。这是本项目唯一别人没有的东西。 |
| **「三大报表老板看不懂，要管理性的大白话财报」** | 管理会计报表 vs 财务会计报表          | 与 v0.1 的 L4「保本营业额」同源。**把财务语言翻译成经营语言**，正是你的职业禀赋。                                   |

**结论：这两条应当成为产品的核心卖点，而不是众多模块中的两个。**

### 1.2 ⚠️ 判断正确、但不是差异化的部分

供应商账期、信用额度、已用额度、临期天数、呆滞天数、安全库存、库位、验收回退、折价、报废原因、盘点——**全部是标准进销存字段**，天财商龙、用友好生意、简道云、猎农均有成熟实现。

**处理方式**：保留，但降级为 T1/T2/T3 层，**不在 M1 实现**。它们的作用是"让 T4 的报表算得准"，不是"让老板每天用"。

### 1.3 ❌ 与项目存亡直接冲突的一条

> 行业教训（联网查证原文）：  
> "批次管理最容易踩的坑，是&#x628A;**'理论上有用的字段'全部变成'每天必须填写的字段'**。我见过一张入库表有二十多个字段，但真正能用于查询的不到一半；仓库人员为了先发货，最后只填商品名称和数量，**批次数据反而失去可信度**。字段必须能够支持实际决策，否则就是录入负担。"

你补充的这一套若全部设为必填：**单店每日录入量 ≈ 60–80 个字段**。而 v0.1 的 P1 原则是「录入零新增动作」，P3 是「允许补录不惩罚」。

**这套需求与 P1/P3 直接冲突。冲突的解法不是删需求，是分级必填（见第 2 节）。**

**3.1.1 供应商评级规则（自动算，不可手改）**

```
评级 = 加权得分
  准时交付率 30%  = 按时到货单数 ÷ 总到货单数
  质量合格率 30%  = (验收数量 − 回退数量) ÷ 验收数量
  价格稳定性 20%  = 1 − (单价标准差 ÷ 单价均值)
  损耗贡献 20%    = 1 − (该供应商来料的损耗金额 ÷ 该供应商进货总额)
A ≥ 90 / B ≥ 80 / C ≥ 70 / D < 70
```

| 字段    | 来源   | 说明                |
| ----- | ---- | ----------------- |
| 出库日期  | 手/自动 |                   |
| 渠道    | 选    | 堂食 / 外卖 / 团购 / 零售 |
| 品名    | 带    |                   |

**⚠ 已证伪**：v0.1 第 2 节已确认小店无法通过对接 API 自动取数（收钱吧未开放自助注册；个人收款码无 API）。因此：

- **M1–M3：出库数量手填或从 POS 日结拍照识别**
- **M4：若客户使用商用收银系统且愿意授权，再评估对接**

**⭐ 由本节衍生出的头号卖点（用户提出，本项目的核心差异）：**

```
账实差异 = 理论库存 − 实际盘点库存
理论耗用 = 期初 + 入库 − 期末（应有）
实际耗用 = Σ 出库单（账面）
差异率 = |理论耗用 − 实际耗用| ÷ 理论耗用
```

**这是内控审计命题，不是 ERP 功能。把它做成产品的第一张报表。**

| 字段       | 来源   | 计算规则                   | 层     |
| -------- | ---- | ---------------------- | ----- |
| 部门       | 主    |                        | T1    |
| 姓名       | 主    |                        | T1    |
| 用工性质     | 主    | 正式工 / 临时工 / 小时工        | T1    |
| 排班       | 手    | 上班/下班时间                | T0/T2 |
| 打卡时间     | 手/自动 |                        | T2    |
| **工时**   | 算    | `(下班 − 上班 + 跨夜) × 24`  | T3    |
| **工时成本** | 算    | 见下                     | T3    |
| 五险金额     | 算    | `缴费基数 × 比例`（基数与比例为主数据） | T3    |
| 公积金金额    | 算    | `缴费基数 × 比例`            | T3    |
| 福利金额     | 算    | `月福利总额 ÷ 月出勤人天 × 当日出勤` | T3    |
| 其他金额     | 手    | 餐补、住宿、补贴               | T2    |

```
全口径工时成本 = 工时 × 小时工价
               + 日均五险  + 日均公积金
               + 日均福利  + 当日其他
其中：日均五险 = 月五险 ÷ 21.75（或直接 ÷ 当月出勤天数）
```

> **用户诉求「把人力成本明晰化」的实现方式**：报表同时给出「**直接工价成本**」和「**全口径人工成本**」两个数。老板看到的是后者，而绝大多数小店只算前者——**这个差额就是他不知道的钱**。

**3.10.1 大白话管理报表（用户提出"老板看不懂三大报表"，本项目答案）**

| 老板的问题        | 大白话指标       | 公式                                  |             |          |
| ------------ | ----------- | ----------------------------------- | ----------- | -------- |
| 我今天做多少才不亏？   | **每日保本营业额** | `月固定成本 ÷ 30 ÷ 毛利率`                  |             |          |
| 我这个月到底赚了多少？  | 落袋利润        | `营业额 − 进货 − 人工 − 房租 − 水电 − 损耗 − 其他` |             |          |
| 钱压在哪了？       | 库存占款        | `Σ 存货金额`，及"其中呆滞 >30 天占 X 元"         |             |          |
| 我还欠谁钱？多久要还？  | 应付账龄清单      | 按供应商列待付金额 + 账期剩余天数，逾期标红             |             |          |
| 哪道菜/哪个货在白养着？ | 单品贡献排名      | 按毛利额降序，末位 10% 标"考虑淘汰"               |             |          |
| 人是不是请多了？     | 全口径人力成本率    | `全口径人工 ÷ 营业额` + 业态区间对照              |             |          |
| 东西是不是在丢？     | **账实差异率**   | \`                                  | 理论耗用 − 实际耗用 | ÷ 理论耗用\` |

## 4. 联网查证后补充：你漏掉的 9 项

| # | 缺项                   | 为什么必须有                                                             | 层      |
| - | -------------------- | ------------------------------------------------------------------ | ------ |
| 1 | **成本卡 / BOM（配方）**    | 餐饮核心。没有 BOM 就算不出菜品理论成本，也算不出理论 vs 实际耗用差异——**直接卡死第 3.5 节的头号卖点**      | T1     |
| 2 | **单位换算率**            | 采购按"箱"、耗用按"克"。行业规范明确"禁止无单位入库"。没有换算率，所有数量对比都是假的                     | T1     |
| 3 | **FEFO（先到期先出）** 出库策略 | 你提到临期天数但没提出库规则。后到货的批次可能生产日期更早，机械 FIFO 会造成临期积压                      | T3     |
| 4 | **盘点差异的审批与成本调整**     | 你只说"正常的盘点单"，未定义盘盈盘亏如何审批、如何入账调成本。不做这个，盘点数据会烂掉                       | T2     |
| 5 | **在途与调拨**            | 单店可不做；一旦有第二家店，没有调拨单就会出现"货在路上但两边都没账"                                | T2（M4） |
| 6 | **发票与三单匹配**          | 你提到"应付"但没提"票"。应付管理的标准是**订单–到货–发票三单匹配**，异常自动标红                      | T2     |
| 7 | **单品毛利 / 菜品贡献度**     | 你只算了整体毛利。行业实证：某西餐厅淘汰 12% 低效菜品后毛利率提升 4.3 个百分点——**这是餐饮毛利提升最有效的单一动作** | T3     |
| 8 | **损耗原因代码表**          | 你列了"报废原因"但未代码化。不代码化就不能聚合分析，等于白记                                    | T1     |
| 9 | **权限分离与双人校验**        | 采购、仓管、财务权限分离；关键节点双人校验。这属于你的内控本行，也是产品可信度的基础                         | T1     |
